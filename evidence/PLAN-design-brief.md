## A. 前提（WORK_ORDER 由来）
- React + Vite、JavaScript（TypeScriptなし）。データ保存は localStorage。データ層は1モジュール（アダプタ）に分離し、Firebase 等へ差し替え可能にする。
- テスト: Vitest（UT/IT1）、Playwright（IT2/ST）。
- 主対象 390px、1280px でも崩れない。
- U1 は 2026-11-15 に決定済み: セグメントは［支出一覧｜在庫｜防災備蓄］の順・この名前で確定。文言は1か所の定数に集約する。
- やらないこと（第9章）: APIキーを使うAI自動生成、通常在庫の期限入力、在庫・防災の独立アプリ化（独立タブ化も不可）、汎用カレンダー/チャット/ToDo。

## C. データ（第6章の5エンティティ＋品目マスタ＋カテゴリ＋設定）
全エンティティ共通: `id`（文字列UUID）、`createdAt`、`updatedAt`（ISO文字列）。日付は `YYYY-MM-DD`（端末ローカル日付）。
- 支出 Expense: date, amount（整数円。下書きでは null 可）, categoryId, itemId（任意）, quantity（整数≥1、品目ありの時のみ。既定1）, memo（任意≤200字）, status（'draft'|'confirmed'）, sourceShoppingItemId（任意。連携①で作られた下書きの元）
- 在庫品目 StockItem: itemId, quantity（整数≥0）, location（'fridge'冷蔵|'freezer'冷凍|'pantry'常温|'bosaiko'防災庫）, registeredDate（自動）, pinned（bool）, refillThreshold（任意・整数≥1、設計案）
- 防災備蓄品 BosaiItem: itemId, quantity（整数≥1）, location（既定 'bosaiko'、他の保管場所も選択可）, kubun（'water'|'food'|'baby'）, expiryDate（必須）
- レシピ Recipe: name, ingredientItemIds（材料タグ＝品目ID配列、1件以上）, servings（人数）
- 買い物リスト項目 ShoppingItem: itemId, quantity（整数≥1）, source（'stock_low'在庫減|'menu_short'献立の不足|'bosai_short'防災の不足）, checked（消し込み済み bool）, checkedAt（任意）, draftExpenseId（任意。①で作った下書き）
- 品目マスタ Item（第6章は項目未定義のため最小定義＝判断）: name（1〜40字、重複不可・前後空白除去）, defaultCategoryId（任意）
- カテゴリ Category（判断で最小定義）: name, linkToStock（bool）, sortOrder。初期: 食費(linkToStock)、日用品(linkToStock)、外食、住まい・光熱、交通、子ども、医療、その他。
- 設定 Settings（仕様の「設定値」を集約）: badgeDays（バッジ/アラートの日数しきい値、既定7）, bosaiTargets（{water, food, baby} 目標量、既定 各0＝未設定）, monthlyIncome（毎月の収入、既定0。ホームの「収支」計算用＝判断）, householdSize（人数、既定2、相談文用）, avoidFoods（避けたい食材、文字列）
- 同じ品目を再購入して在庫に追加した場合は、既存行に合算せず新しい行（ロット）を作る（登録日＝経過日数を保つため。判断）。

## D. 連携ルール（D3。金額は自動確定しない）
- ① 消し込み→支出下書き: 買い物リスト項目をチェックすると Expense(status=draft, amount=null, date=今日, categoryId=品目の既定カテゴリ or 食費, itemId, quantity, memo='買い物リストから', sourceShoppingItemId) を作成。チェックを外すと、その下書きが未確定なら下書きを削除。確定済みなら外せない（理由を表示）。下書きは支出ハブ「支出一覧」の先頭「確認待ちの下書き」欄に出し、タップで登録シート（下書き確認モード）を開く。金額（必須）を入力し「確定」で status=confirmed。下書き削除も可（元の買い物項目は未消し込みに戻す）。ホームのアラート対象には入れない。確定時、シートの「在庫に追加」トグルは既定オフ（本人が選ぶ）。
- ② 在庫減→買い物リスト: 在庫行の数量を減らした結果、その品目の在庫合計がしきい値を「下回った」（合計 < しきい値 かつ 減らす前の合計 ≥ しきい値）とき、ShoppingItem(source=stock_low, quantity=max(1, しきい値−合計)) を追加。同じ品目の未消し込み項目が既にあれば追加しない。品目のしきい値は、その品目の在庫行が持つ refillThreshold の最大値（未設定なら連携しない）。数量0の行は自動削除しない（0として表示、手動削除可）。
- ③ 献立決定→不足食材と在庫減: 献立（案Aのレシピ、または手入力の献立名＋材料選択）を「この献立に決める」と確認ダイアログを出す。材料ごとに「使う量」（既定1、0〜在庫合計）を調整可。確定で、在庫合計0の材料は ShoppingItem(source=menu_short, quantity=1)（同品目の未消し込みがあれば追加しない）、在庫ありの材料は使う量だけ減らす（登録日が古い行から順に減らす＝FIFO）。在庫減で②の条件を満たせば②も連鎖する。手入力の献立はレシピとして保存しない。
- ④ 優先付け→献立候補の先頭: 下記 F の並び順で実現。
- ⑤ 購入価格の蓄積と食費の見通し: 確定済みかつ品目と数量のある支出から品目別の平均単価（Σ金額/Σ数量、円未満四捨五入）を算出。食費の見通し＝今月の確定済み「食費」合計＋見込み額。【改訂 2026-11-15 ED レビュー後】見込み額の対象は、品目の既定カテゴリが「食費」の買い物リスト項目のうち、未消し込み（P0）と消し込み済みで下書きが未確定（P1）のもの（数量×平均単価）。単価不明の品目は0円として件数を別表示、既定カテゴリ未設定の品目は見込みに入れず「カテゴリ未設定 n件」として別表示。ホームとグラフに表示。
- 【追加 2026-11-15 ED レビュー後】しきい値の保持: 在庫行を新しく作るとき（支出シート・在庫追加シートとも）、その品目の現在のしきい値 T（既存行の refillThreshold の最大値）を refillThreshold に引き継ぐ（利用者が上書き可）。在庫行の編集で連携②を判定するときは保存後の T を使う。品目を変えた編集では、元の品目について「減った」として②を判定する。

## E. アラート/バッジ（第7章）
- 対象は防災備蓄品の期限のみ。残日数 = expiryDate − 今日（日単位、ローカル日付）。
- 対象件数 = 数量≥1 かつ 残日数 ≤ badgeDays の防災備蓄品（期限切れ＝残日数<0 を含む）。支出タブのバッジに件数（0なら非表示、100以上は「99+」）。
- ホームの文脈カードは最大1枚。件数>0のときだけ出す。表示内容は残日数が最小の品（期限切れ優先）と件数。タップで `/expenses?tab=bosai`。
- 通常在庫・下書き・買い物リストはアラート/バッジ対象外。

## F. 計算ロジック
- 経過日数 d = 今日 − registeredDate（日数、登録当日0）。表示は「{d+1}日目」（登録当日が1日目）。
- 在庫一覧の並び: ピン付き優先 → d 降順 → 品目名昇順 → id。保管場所チップ（すべて/冷蔵/冷凍/常温/防災庫）で絞り込み。
- 充足率（区分ごと）: 現在量 = その区分で期限切れでない（残日数≥0）防災備蓄品の数量合計。充足率 = min(現在量/目標量, 1)。目標量0（未設定）はバーを出さず「目標未設定」。不足数 = max(0, 目標量−現在量)。不足>0の区分に「買い物リストに追加」ボタン→ダイアログ（品目: その区分の既存品目から選択 or 品目マスタから選択、数量: 既定=不足数）→ ShoppingItem(source=bosai_short)。
- 献立候補の並び（案A）: 在庫あり材料数（在庫合計>0の材料タグ数）降順 → 在庫あり材料の最大経過日数降順 → ピン付き材料数降順 → レシピ名昇順。【改訂 2026-11-15 ED レビュー後】仕様4.4「併用の日常フロー」の「在庫・経過日数・ピンの順で並ぶ」に文言どおり合わせる（当初案のピン優先は撤回）。各候補に「在庫あり n/m」「不足: …」を表示。
- 今月の収支 = monthlyIncome − 今月の確定済み支出合計。今月の支出合計は確定済みのみ（下書きは含めず、下書き件数・未確定を別表示）。
- 相談文（案B）: 固定テンプレート。入力条件は献立画面で 人数（既定=設定）、避けたい食材（既定=設定）、作りたい品数（既定3）。本文に 在庫（品目合算・数量、防災備蓄品は含めない）、優先して使いたい品（ピン付き＋経過日数上位5件、重複除去）、条件を埋め込む。コピーは navigator.clipboard.writeText、失敗時は選択可能なテキスト欄に表示して手動コピーを促す。AIへの送信・結果取り込みは一切しない（D4）。

## G. バリデーション（主なもの）
- 支出: 日付必須・実在日付。金額は確定時必須・整数・1〜9,999,999。カテゴリ必須。品目は任意（「在庫に追加」オン時は必須）。数量 整数1〜999。メモ≤200字。
- 在庫に追加オン: 保管場所必須。保管場所=防災庫のときだけ「防災備蓄として登録」チェックを表示。チェック時は区分・期限必須で、StockItem ではなく BosaiItem を作る（第6章: 別エンティティ）。
- 在庫数量 整数0〜999。しきい値 空 or 整数1〜999。防災 数量1〜999・期限必須。品目名 1〜40字。設定の数値は整数0以上（badgeDays 0〜365、人数1〜20、目標量0〜9999、収入0〜99,999,999）。

## H. 非機能
- 対象ブラウザ: iOS Safari 16 以上、Android Chrome 最新、デスクトップ Chrome/Edge/Safari 最新。
- レスポンシブ: 320〜1280px で横スクロールなし、主対象 390px。1280px では本文最大幅を制限して中央寄せ（例 max-width 560px のモバイルレイアウトを中央に）。
- localStorage の前提と限界: 端末・ブラウザごとに独立（夫婦間で共有・同期されない）、容量目安 5MB、ブラウザのデータ削除/プライベートモード/Safari の長期未使用時の削除で消える、同時編集の整合なし。キーは `kakeibo:v1:<collection>`、`kakeibo:v1:meta` にスキーマ版。書込み失敗（QuotaExceeded）はエラー表示。

## I. ID の方針
- 構成: `src/data/`（storageAdapter＝localStorage 実装のみがブラウザAPIに触れる、repository＝コレクション単位の非同期 CRUD）、`src/domain/`（純関数: dates, stock, bosai, menu, consult, forecast, validation, alerts）、`src/services/`（連携ルールを repository 越しに実行するユースケース関数）、`src/state/`（AppStore: React Context＋useReducer、起動時に全コレクションをロードしメモリに保持。書込みは services 経由→成功後に state 更新）、`src/components/`, `src/pages/`, `src/constants/`（セグメント文言・保管場所・区分・初期カテゴリ）, `src/seed/`（初期品目マスタと定番レシピ30品）。
- データ層 API は Promise を返す（将来 Firebase に差し替えても呼び出し側を変えないため）。
- 「今日」は注入可能（`today` 引数 or clock モジュール）にしてテストで固定する。
- 初期レシピ30品は一般的な家庭の定番で仮置き（家の定番は未入手のため。判断）。
- テスト方針: UT＝domain/validation/data 層、IT1＝services 経由の連携①〜⑤と下書き→確定、IT2＝Playwright で遷移6段・セグメント・トグル条件表示、ST＝全画面×390/1280 スクショ＋E2E。
