# UAT/RT 項目表（受入・リリース確認）

- 基準: 仕様書 v1.1（`docs/spec-v1.1.html`）の決定事項 D1〜D6、設計案 S1〜S3、第9章「やらないこと」
- 実施日: 2026-11-15
- 判定方法: 各決定に対応する UT / IT1 / IT2 / ST の実施結果と、ソースコードの機械確認（grep）を根拠に判定
- 結果: **全件適合。リリース可（判定は末尾）**

## 決定事項への適合
| ID | 決定 | 判定 | 根拠 |
|---|---|---|---|
| UAT-D1 | ログイン直後は家計簿ホーム | 適合 | IT2-01（起動直後に家計簿ホームと今月の収支を確認）。認証は持たないため「起動直後」と読み替え（ED の前提として明記） |
| UAT-D2 | 在庫・防災は支出の中（支出ハブ＋補助導線、セグメント［支出一覧｜在庫｜防災備蓄］） | 適合 | UT-G05（セグメントの並びと名前を定数で固定）、IT2-05/06/07（切替）、IT2-04/08/11（補助導線=文脈カード・登録シート内トグル・カテゴリ詳細リンク） |
| UAT-D3 | 家計簿⇔在庫の常時連携5本、金額は下書き→確認で確定 | 適合 | 連携① IT1-09〜13・IT2-09、② IT1-14〜20b、③ IT1-21〜25・ST-10、④ UT-M04〜07、⑤ UT-F01〜08。自動確定がないことは IT1-11（金額なしでは確定不可）で確認 |
| UAT-D4 | APIキー不使用・アプリ内AI自動生成なし | 適合 | ソース全体に外部通信（fetch/XHR）・APIキー・外部URL の記述なし（grep で機械確認）。相談文は決定的な文字列組み立てのみ（UT-C、Codex レビューでも確認） |
| UAT-D5 | 期限入力は防災備蓄のみ、通常在庫は品目・数量・保管場所 | 適合 | 在庫の項目に期限がないこと（UT-S、IT1-04=防災庫の通常在庫も期限なし、画面 ST-03）。期限の表示・計算は防災備蓄だけ（ソース確認） |
| UAT-D6 | 献立は案A（定番DB）＋案B（相談ボタン）の併用 | 適合 | 案A: UT-G01（30品）・UT-M（並び）・IT2-10。案B: UT-C・IT2-10（相談文が生成されコピー導線がある） |

## 「やらないこと」（仕様書第9章）の確認
| 項目 | 判定 | 根拠 |
|---|---|---|
| APIキーを使うAI自動生成 | していない | UAT-D4 と同じ |
| 通常在庫への期限入力 | していない | UAT-D5 と同じ |

## リリース確認（RT）
| 項目 | 結果 |
|---|---|
| ビルド | 成功（`npm run build`、エラーなし） |
| 全テスト | UT 61件 + IT1 31件 = 92件 全件合格（`npm test`） |
| 画面崩れ | 全9画面 × 390px/1280px で横はみ出しなし・目視崩れなし（ST） |
| 既知の制限 | (1) データは端末のブラウザ内保存（localStorage）のため、夫婦間での自動同期はされない。ブラウザのデータ削除で消える (2) 初期レシピ30品は仮置き (3) 対象ブラウザは ED 記載の範囲で確認（実機 iOS Safari は未確認、Chrome 系で検証） |
| 判定 | **リリース可**（上記の制限を理解したうえで、家族内利用を開始できる状態） |
