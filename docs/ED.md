### 0.1 用語

| 用語 | 意味 |
|---|---|
| 今日 | 端末のローカル日付（`YYYY-MM-DD`）。画面表示時とアプリが前面に戻った時に取り直す |
| 今月 | 今日が属する暦月（1日〜末日）。支出の「日付」で判定する |
| 確定済み支出 | 状態が `confirmed` の支出 |
| 下書き | 状態が `draft` の支出。連携①でのみ作られる |
| 在庫合計 | ある品目について、在庫品目（StockItem）の数量の合計。防災備蓄品（BosaiItem）は含めない |
| 経過日数 d | 今日 − 登録日（日数）。登録当日は 0 |
| 残日数 | 防災備蓄品の 期限 − 今日（日数）。当日は 0、期限切れは負 |
| シート | 画面下からせり上がるモーダル（ルートを持たないオーバーレイ） |
| ダイアログ | 画面中央に出るモーダル（ルートを持たないオーバーレイ） |

## 1. 設計上の前提・判断

| No | 判断の内容 | 出所 | 根拠 |

| J-08 | 在庫数量が 0 になった行は自動削除しない（0 として表示、手動削除可） | B | 「切らしている」ことが一覧で分かる方が補充判断に役立つため |

|---|---|
| 「AIに相談する文をコピー」 | 検証 OK なら相談文（下記テンプレート）を組み立て、クリップボードにコピー。成功: トースト「相談文をコピーしました。お使いのAIサービスに貼り付けてください」。失敗: ボタンの下に読み取り専用のテキスト欄で相談文を表示し「コピーできませんでした。下の文を長押しで選択してコピーしてください」 |

**相談文テンプレート**（`{}` は差し込み。行頭の「- 」は箇条書き）

```
今ある食材で作れる献立を相談させてください。

【条件】
- 人数: {人数}人
- 作りたい品数: {品数}品
- 避けたい食材: {避けたい食材。空なら「なし」}

【優先して使いたい食材】
- {品目名}（{経過日数表示}{ピン付きなら「、そろそろ使いたい」}）
（該当なしなら「- 特になし」）

【今ある食材と数量】
- {品目名} {在庫合計}
（在庫なしなら「- なし」）

上の食材をできるだけ使い、優先して使いたい食材から使う献立を{品数}品提案してください。足りない食材があれば、買い足すものとして分けて書いてください。
```

- 「今ある食材」: 在庫品目を品目ごとに合算し、在庫合計 > 0 の品目を品目名昇順。防災備蓄品は含めない。
- 「優先して使いたい食材」: 在庫合計 > 0 の品目のうち、ピン付き（数量 > 0 の行にピンがある）品目すべて（経過日数降順）と、経過日数降順の上位5品目を重複除去して、ピン付きを先に並べる（J-31）。品目の経過日数は数量 > 0 の行の最大値。
- 期限に関する情報は含めない（通常在庫は期限を持たない、D5）。

## 5. 連携ルールの振る舞い

D3 の5本。**どれも金額を自動確定しない。** 金額を持つ支出は、新規入力（本人が入力）か連携①の下書き（本人が確認して確定）でのみ確定済みになる。

### 5.1 連携① 消し込み → 支出の下書き

| 観点 | 内容 |
|---|---|
| トリガー | SC-04 で未消し込みの項目にチェックを付ける |
| 前提条件 | 項目が `checked=false` |
| 処理 | 1. 支出を作成: status='draft'、amount=null、date=今日、categoryId=品目の既定カテゴリ（無ければ 'food'）、itemId、quantity=項目の数量、memo='買い物リストから'、sourceShoppingItemId=項目 id。2. 項目を更新: checked=true、checkedAt=現在日時、draftExpenseId=作成した支出の id |
| 生成／更新データ | Expense（draft）1件作成、ShoppingItem 1件更新 |
| 重複時の扱い | すでに checked=true の項目には起きない（チェック操作の対象外）。1項目につき下書きは最大1件 |
| 取消時の扱い | チェックを外す: 下書きが draft なら下書きを削除し、項目を checked=false、checkedAt=null、draftExpenseId=null に戻す。confirmed なら外せない（「この項目の支出は確定済みのため、チェックを外せません」）。draftExpenseId=null（支出削除済み）なら項目だけ未消し込みに戻す |
| 金額の扱い | 金額は入れない（null）。SC-03 下書き確認モードで本人が入力し「確定する」で confirmed（5.6）。下書きの金額は今月の支出合計・確定食費・平均単価に含めない（食費の見通しでは、元の買い物項目を P1 として「数量 × 平均単価」の見込みに数える。5.5）。ホームのアラート・支出タブのバッジの対象外 |
| 例 | 「牛乳 ×2（在庫減）」をチェック → 支出一覧の「確認待ちの下書き」に「11/15 牛乳 ×2 金額未入力」が出る → 本人が 398 円と入力して確定 → 今月の食費に 398 円が加わり、牛乳の平均単価は 199 円 |

### 5.2 連携② 在庫減 → 買い物リスト

| 観点 | 内容 |
|---|---|
| トリガー | 在庫品目の数量を減らす操作: SC-02 在庫の「−」、AX-01 編集で数量を下げて保存、連携③の在庫減（J-23） |
| 前提条件 | その品目のしきい値 T が存在する。T = その品目の在庫品目（StockItem）行の refillThreshold の最大値で、操作を保存した後の値で求める。全行が null（または行が無い）なら連携しない（J-07） |
| しきい値の引き継ぎ | 在庫行を新しく作るとき（支出登録シート・AX-01 とも）は、その時点の T を新しい行の refillThreshold に入れる（AX-01 では上書き可）（J-07a） |
| 処理 | 減らす前の在庫合計 B と減らした後の在庫合計 A を求め、保存後の T で A < T かつ B ≥ T のとき ShoppingItem(itemId, quantity=max(1, T − A), source='stock_low', checked=false) を作成。品目を変えた編集では、元の品目について B=変更前の合計、A=その行を除いた合計として判定する |
| 生成／更新データ | ShoppingItem 0〜1件作成 |
| 重複時の扱い | 同じ品目の未消し込み項目（発生源を問わない）が既にあれば作成しない |
| 取消時の扱い | 後から数量を増やしても、作成済みの買い物項目は自動では消さない（必要なら SC-04 で削除）。在庫行の削除・しきい値の変更では起きない |
| 金額の扱い | 金額は関わらない |
| 例 | 卵（T=6）の在庫合計 6 → 「−」で 5: B=6 ≥ 6、A=5 < 6 → 「卵 ×1（在庫減）」を追加。さらに 4 に減らしても B=5 < 6 のため追加しない（下回った瞬間の1回だけ）。合計 7 → 6 は A=6 < 6 が偽のため追加しない。数量と T を同時に変えた例: 卵の行 X（数量4、T=6）と行 Y（数量3、T=6）で合計 7。AX-01 で行 X を「数量 4→1、補充の目安数量 6→5」に変えて保存 → 保存後の T = max(5, 6) = 6、B=7 ≥ 6、A=4 < 6 → 「卵 ×2（在庫減）」を追加。同じ操作で行 X の目安を 9 にした場合は、保存後の T=9 で B=7 ≥ 9 が偽のため追加しない（もともと下回っていた扱い）。品目を変えた例: 行 X（卵、数量4）の品目を「うずら卵」に変えて保存 → 卵は B=7、A=3、保存後の T=6（行 Y）で追加される |

### 5.3 連携③ 献立決定 → 不足食材と在庫減

| 観点 | 内容 |
|---|---|
| トリガー | AX-03 で「決める」（案Aのレシピ、または手入力の献立） |
| 前提条件 | AX-03 の検証が OK |
| 処理 | 材料ごとに: (a) 在庫合計 = 0 → ShoppingItem(quantity=1, source='menu_short') を作成。(b) 在庫合計 > 0 かつ 使う量 u > 0 → 数量 > 0 の行を登録日昇順（同日は createdAt 昇順）に並べ、u を使い切るまで各行の数量を減らす（FIFO、J-09）。減らした品目ごとに連携②を判定する。(c) u = 0 → 何もしない |
| 生成／更新データ | ShoppingItem 0〜n件作成、StockItem 0〜n件更新、（②の連鎖で）ShoppingItem 0〜n件作成 |
| 重複時の扱い | (a) で同じ品目の未消し込み項目が既にあれば作成しない。②の重複規則は 5.2 |
| 取消時の扱い | 取り消し操作は持たない。誤りは在庫の「＋」と買い物項目の削除で手動で直す |
| 金額の扱い | 金額は関わらない |
| 例 | 肉じゃが: 豚肉（在庫 1 行 ×2、9日目）、じゃがいも（2行 ×3＝12日目、×2＝2日目）、玉ねぎ（0）、にんじん（×1）。使う量 豚肉1・じゃがいも4・にんじん1 → 豚肉 2→1、じゃがいも 12日目の行 3→0・2日目の行 2→1、にんじん 1→0、玉ねぎを買い物リスト（献立の不足 ×1）に追加。にんじんの T=1 なら B=1 ≥ 1、A=0 < 1 で「にんじん ×1（在庫減）」も追加 |

### 5.4 連携④ 優先付け → 献立候補の先頭

| 観点 | 内容 |
|---|---|
| トリガー | SC-05 の表示時（在庫・ピンの変更は次の表示で反映） |
| 前提条件 | なし |
| 処理 | レシピごとに: 在庫あり材料数 n（在庫合計 > 0 の材料タグ数）、ピン付き材料数 p（在庫合計 > 0 かつ数量 > 0 の行にピンがある材料数）、最大経過日数 e（在庫あり材料の、数量 > 0 の行の経過日数の最大値。在庫あり材料が無ければ −1）。並び: n 降順 → e 降順 → p 降順 → レシピ名昇順（J-11。仕様 4.4 の「在庫・経過日数・ピンの順」）。期限は使わない（D5） |
| 生成／更新データ | なし（表示のみ） |
| 重複時の扱い | 該当なし |
| 取消時の扱い | 該当なし（ピンを外せば次の表示で並びが戻る） |
| 金額の扱い | 金額は関わらない |
| 例 | 親子丼（n=3、e=19＝20日目の品あり、p=0）、豚の生姜焼き（n=3、e=4＝5日目、p=1）→ n が同じなので e の大きい親子丼が先（ピンより経過日数が優先）。n・e が同じなら p の大きいレシピが先。n=2 のレシピは e・p に関係なく n=3 のレシピより後 |

### 5.5 連携⑤ 購入価格の蓄積と食費の見通し

| 観点 | 内容 |
|---|---|
| トリガー | SC-01・SC-06 の表示時、SC-04 の見込み額表示時 |
| 前提条件 | なし |
| 処理 | 品目別の平均単価 = Σ金額 ÷ Σ数量（status='confirmed' かつ itemId と quantity がある支出、全期間）。円未満は四捨五入。食費の見通し = 今月の確定済み「食費」合計 ＋ 買い物予定分。買い物予定分 = 品目の既定カテゴリが「食費」の買い物リスト項目のうち、未消し込み（P0）と消し込み済みで下書きが未確定（P1）のものの Σ（数量 × 平均単価）（J-12）。平均単価が無い品目は 0 円として件数（単価不明 k件）を別表示。既定カテゴリが未設定の品目の項目（P0・P1）は見込みに入れず、件数を「カテゴリ未設定 n件」として別表示。既定カテゴリが食費以外の項目は数えない |
| 生成／更新データ | なし（集計のみ。単価は保存せず毎回算出） |
| 重複時の扱い | 該当なし |
| 取消時の扱い | 支出の編集・削除は次の表示で集計に反映 |
| 金額の扱い | 下書き（amount=null）の金額は平均単価にも確定食費にも含めない（P1 の項目は「数量 × 平均単価」の見込みとしてだけ数える）。見通しは表示用の見込みで、支出として登録・確定しない |
| 例 | 牛乳: 確定済み 2件（数量2で金額398円、数量1で金額220円）→ (398＋220) ÷ (2＋1) = 206円。買い物リスト: 未購入「牛乳 ×2」（食費）、購入済みで下書き確認待ち「卵 ×1」（食費、平均単価 250円）、未購入「にら ×1」（食費、単価なし）、未購入「キッチンペーパー ×1」（既定カテゴリ未設定）、未購入「おむつ ×1」（日用品）。今月の確定食費 12,000円 → 見通し 12,000 ＋ 412 ＋ 250 ＋ 0 = 12,662円、単価不明 1件、カテゴリ未設定 1件（おむつは数えない） |

### 5.6 下書き → 確定フローの状態遷移

買い物リスト項目（ShoppingItem）と下書き支出（Expense）の組の状態。

| 状態 | ShoppingItem.checked | draftExpenseId | Expense.status | SC-04 の表示 |
|---|---|---|---|---|
| P0 未購入 | false | null | （支出なし） | 未購入 |
| P1 下書き確認待ち | true | 支出 id | draft | 購入済み「下書き確認待ち」 |
| P2 確定済み | true | 支出 id | confirmed | 購入済み「支出を確定済み」 |
| P3 支出なし | true | null | （確定後に削除済み） | 購入済み「支出なし」 |

| 遷移元 | イベント | 遷移先 | 処理 | 可否 |
|---|---|---|---|---|
| P0 | チェック（連携①） | P1 | 下書き作成、項目を消し込み | 可 |
| P1 | 下書き確認で「確定する」（金額入力済み） | P2 | 支出を confirmed に更新 | 可（金額未入力は不可） |
| P1 | 「下書きを削除」 | P0 | 下書き削除、項目の checked=false・checkedAt=null・draftExpenseId=null | 可 |
| P1 | チェックを外す（消し込み解除） | P0 | 同上（下書き削除） | 可 |
| P1 | 買い物項目の削除 | — | — | 不可（削除ボタンを出さない、J-20） |
| P2 | チェックを外す | P2 のまま | トースト「この項目の支出は確定済みのため、チェックを外せません」 | 不可 |
| P2 | 支出の削除（SC-03 編集） | P3 | 支出削除、項目の draftExpenseId=null | 可（J-19） |
| P2 | 買い物項目の削除 | （項目なし） | 項目のみ削除。支出は残る（sourceShoppingItemId は履歴として残す） | 可 |
| P3 | チェックを外す | P0 | 項目を未消し込みに戻す | 可 |
| P3 | 買い物項目の削除 | （項目なし） | 項目を削除 | 可 |

draft から confirmed への変更は「確定する」操作のみ。confirmed から draft に戻す操作は無い。

## 6. アラート／バッジ規則

### 6.1 対象

- 対象は**防災備蓄品（BosaiItem）の期限のみ**（仕様第7章）。
- 対象外: 通常在庫（保管場所が防災庫の在庫品目を含む）、支出の下書き、買い物リスト、その他すべて。通常在庫は在庫画面の経過日数とピンで確認する。

### 6.2 件数の定義

- 残日数 = expiryDate − 今日（日単位、端末ローカル日付）。
- 対象件数 = 数量 ≥ 1 かつ 残日数 ≤ badgeDays の防災備蓄品の件数（行数）。期限切れ（残日数 < 0）を含む。
- 支出タブのバッジ: 対象件数。0 は非表示、100 以上は「99+」。
- 今日が変わったら（画面表示時・前面復帰時）再計算する。設定の badgeDays 変更、防災備蓄品の追加・編集・削除の直後にも再計算する。

### 6.3 境界値の例（今日 = 2026-11-15、badgeDays = 7）

| 期限 | 残日数 | 対象 | 一覧の残日数文言 | 状態ラベル |
|---|---|---|---|---|
| 2026-11-22 | 7（= badgeDays） | 対象 | あと 7 日 | 期限が近い |
| 2026-11-23 | 8（= badgeDays+1） | 対象外 | あと 8 日 | なし |
| 2026-11-15 | 0 | 対象 | 今日が期限 | 期限が近い |
| 2026-11-14 | −1 | 対象 | 期限切れ（1日経過） | 期限切れ |

badgeDays = 0 のときは、残日数 0（今日が期限）と期限切れだけが対象。

### 6.4 ホームの文脈カード

| 項目 | 規則 |
|---|---|
| 枚数 | 最大1枚。対象件数 > 0 のときだけ出す |
| 選ぶ品 | 対象のうち残日数が最小の品（期限切れが自然に優先される）。同値は品目名昇順 → id 昇順 |
| 見出し | 「防災備蓄の期限が近い品があります」 |
| 本文 | 選んだ品が 期限切れ:「{品目名}（{区分名}）が期限切れです（{n}日経過）」、残日数 0:「{品目名}（{区分名}）は今日が期限です」、残日数 > 0:「{品目名}（{区分名}）の期限まであと{n}日です（{YYYY-MM-DD}）」 |
| 件数 | 対象件数 ≥ 2 のとき「ほか{件数−1}件」 |
| 操作 | カード全体がボタン。文言「防災備蓄を見る」。タップで `/expenses?tab=bosai`（T2） |
| 表示 | 注意アイコン＋文字で示す（色だけに頼らない） |

| 前提 | データはブラウザの localStorage に保存する。サーバー・外部サービスには接続しない |
| データ層 | データ層は1モジュール（アダプタ）に分離し、localStorage に触れるのはこのモジュールだけにする。呼び出し側の API は非同期（Promise）とし、将来 Firebase 等に差し替えても画面側を変えない |
| キー | `kakeibo:v1:<collection>`（expenses、stockItems、bosaiItems、recipes、shoppingItems、items、categories）、`kakeibo:v1:settings`、`kakeibo:v1:meta`（スキーマ版 `schemaVersion`） |
| 限界1 共有 | 端末・ブラウザごとに独立。夫婦の端末間で共有・同期されない |
| 限界2 容量 | 目安 5MB。超えると書き込みに失敗する |
| 限界3 消失 | ブラウザのデータ削除、プライベートブラウズ、Safari の長期間未使用時の自動削除などで消える。バックアップ機能は持たない |
| 限界4 同時編集 | 同じブラウザの複数タブで同時に編集した場合の整合は取らない（後から書いた方が残る） |
| 書き込み失敗 | 3.0.6 のエラー表示。保存前の状態を保つ |
| 読み込み失敗 | 保存データが壊れていて読めない場合は「データを読み込めませんでした。データは変更していません」と表示し、そのコレクションへの書き込みを止める（上書きによる消失を防ぐ） |
| 使えない環境 | localStorage が使えない場合は画面上部に「この環境ではデータを保存できません」を常時表示する |

### 7.5 アクセシビリティ（最低限）

- タップ領域は 44×44px 以上（ボタン、チップ、チェックボックス、ステッパー、下部タブ、セグメント、ピン）。
- すべての入力にラベルを付ける（`<label>` または `aria-label`）。エラーは `aria-describedby` で入力に結び付ける。
- 色だけに頼らない: 選択状態（太字・線・`aria-selected`/`aria-pressed`）、期限切れ・期限が近い（アイコン＋文字）、赤字（「−」と「赤字」）、在庫あり／なし（✓／— と文字）。
- 文字と背景のコントラスト比 4.5:1 以上。
- キーボード操作: フォーカス表示を消さない。オーバーレイはフォーカスを閉じ込め、Esc で閉じる。
- トーストは `role="status"`（エラーは `role="alert"`）。

### 7.6 文言の定数化

次の文言は定数モジュール（`src/constants/`）に1か所で定義し、画面・テストから参照する。

- セグメント名と並び［支出一覧｜在庫｜防災備蓄］とクエリ値（list／stock／bosai）。U1 は決定済みだが、文言を変える場合もこの1か所の変更で済むようにする。
- 下部タブ名（家計簿・支出・グラフ・設定）。
- 保管場所・区分・発生源・状態の表示名。
- バリデーションのエラーメッセージ、トースト文言、空状態の文言。

### 7.7 性能の目安（目標値。実測ではない）

| 項目 | 目安 |
|---|---|
| 想定データ量 | 支出 5,000 件、在庫 300 行、防災 100 件、買い物 200 件、レシピ 30 品 |
| 初回表示 | 一般的なスマートフォンで 2 秒以内に操作可能 |
| 操作の反映 | 保存・チェック・セグメント切替の結果が 100ms 程度で画面に反映 |

### 7.8 エラー時の表示

| 状況 | 表示 |
|---|---|
| 入力エラー | 各項目の直下にメッセージ（3章）。最初のエラー項目にフォーカス |
| 保存失敗 | エラートースト（3.0.6） |
| 読み込み失敗 | 7.4 |
| 存在しないデータを開いた（削除済みの支出など） | トースト「対象のデータが見つかりません」を出してオーバーレイを開かない |
| 存在しないルート | `/` に置き換え（J-39） |
| 存在しないカテゴリ | SC-07 のエラー表示（T32） |
| クリップボード失敗 | 3.5.4 の手動コピー表示 |
| 想定外の例外 | 画面全体に「問題が発生しました。再読み込みしてください」と「再読み込み」ボタン（データは変更しない） |

## 8. やらないこと

### 8.1 仕様書第9章の再掲

- API キーを使う AI 自動生成（D4）。相談文はコピーするだけで、AI への送信・結果の取り込みはしない。
- 通常在庫への期限入力（D5）。在庫品目には期限の項目・入力欄・表示を持たない。
- 在庫・防災の独立アプリ化（D2）。独立した下部タブも作らない。
- 汎用カレンダー、チャット、汎用 ToDo。

### 8.2 ED で範囲外とした事項

| 事項 | 理由 |
|---|---|
| ログイン・アカウント・夫婦間の共有／同期 | localStorage 単体の前提（J-03、7.4） |
| Firebase 等の外部サービス接続 | WORK_ORDER の禁止事項。データ層の差し替え口だけ用意する |
| データのエクスポート／インポート、バックアップ | 仕様にない |
| カテゴリの追加・名前変更・削除 | J-28 |
| レシピの追加・編集・削除画面 | J-25 |
| 手入力献立のレシピ保存 | J-10 |
| 買い物リストへの手動追加 | J-21 |
| 月の切替（グラフ・カテゴリ詳細）、予算機能 | J-35。仕様にない |
| 月ごとの収入の記録 | J-13 |
| 数量の単位 | J-29 |
| 通常在庫のアラート・バッジ、下書き・買い物リストのアラート・バッジ | 仕様第7章 |
| プッシュ通知・メール通知 | 仕様にない |
| レシート読み取り、価格の自動入力、金額の自動確定 | D3（金額は本人が確定） |
| 献立決定の取り消し操作 | 5.3（手動で直す） |
| 将来候補（育児交代ログ、家事当番など仕様第10章） | 今回は作らない（仕様第10章） |
