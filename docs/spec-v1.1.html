3全体構成と画面

下部タブ

家計簿支出グラフ設定

在庫と防災備蓄は下部タブに出さず、「支出」タブの中のセグメントで切り替える（D2）。

画面5点の役割

家計簿ホーム

ログイン直後の画面（D1）。今月の収支と、必要なときだけ文脈カードを1枚表示する。

支出ハブ（一覧）

支出タブの既定表示。上部セグメント［支出一覧｜在庫｜防災備蓄］の起点。

在庫

セグメント「在庫」。品目・数量・保管場所と経過日数、ピンを表示する。期限は扱わない。

防災備蓄

セグメント「防災備蓄」。期限と充足バーを表示する。アプリ内で期限を持つ唯一の画面。

支出登録シート

支出を登録するシート。「在庫に追加」トグルと、条件付きの防災登録チェックを持つ。

決定済みこの章のセグメントの表示名［支出一覧｜在庫｜防災備蓄］と並びは 2026-11-15 に決定（U1）。

画面遷移

UI検討レポートの遷移を基に、バッジとアラートの対象を防災備蓄の期限だけに直したもの。

  1. ログイン後、家計簿ホームを開く今月の収支を表示する。防災備蓄に期限の近い品があるときだけ、文脈カードを1枚出す。
  2. ホームの文脈カードから防災備蓄へカードをタップすると、支出タブのセグメント「防災備蓄」が選ばれた状態で開く。
  3. 下部タブ「支出」で支出ハブを開く既定は「支出一覧」。タブのバッジは防災備蓄の期限件数だけを示す。
  4. セグメントで在庫・防災備蓄を切り替える［支出一覧｜在庫｜防災備蓄］を同じ画面上で切り替える。
  5. 支出登録シートで支出を記録する「在庫に追加」をオンにすると、品目が在庫にも入る。設計案「在庫に追加」がオンで保管場所に防災庫を選んだときだけ、防災登録チェックも出る。
  6. カテゴリ詳細から在庫へ食費などのカテゴリ詳細にあるリンクから、関連する在庫に移る。

4機能仕様

4.1 家計簿

ホームの表示要素

  • 今月の支出合計と収支
  • カテゴリ別の内訳（詳細は「グラフ」タブ）
  • 文脈カード（最大1枚）: 防災備蓄の期限が近いときだけ出す。アラートの規則は第7章。確認待ちの支出下書きはホームのアラート対象に入れず、支出ハブ側で確認する。

支出登録の項目

  • 日付、金額、カテゴリ、品目（品目マスタから選択、または新規）、数量、メモ
  • 「在庫に追加」トグル: オンにすると、品目と数量を在庫に登録する。保管場所を選ぶ欄が出る。
  • 設計案防災登録チェック: 「在庫に追加」がオンで保管場所に防災庫を選んだときだけ表示する。チェックすると防災備蓄品として登録し、期限の入力欄が出る。

4.2 在庫

  • 項目: 品目、数量、保管場所（登録日は自動記録）。期限欄はない（D5）。
  • 設計案経過日数の自動表示: 登録日からの日数を「◯日目」と表示し、経過日数の多い順に並べる（S1）。
  • 設計案ピン: 「そろそろ使いたい」を1タップで付け外しする。ピン付きの品は一覧の先頭に寄せる（S1）。
  • 保管場所チップで絞り込む。設計案チップの例: 冷蔵冷凍常温防災庫
  • 数量を減らすと、しきい値を下回った品は買い物リストに入る（第5章 連携②）。設計案しきい値は設定値（品目ごと任意）とし、在庫品目の任意項目「補充の目安数量」で持つ。

4.3 防災備蓄

  • 項目: 品目、数量、保管場所、期限、区分（水・食料・赤ちゃん用品）。
  • 充足バー: 区分ごとに目標量に対する現在量を表示する。目標量は設定で決める。

表示例・値に意味はない（バーの長さはすべて同じにしている）

水
食料
赤ちゃん用品
  • 不足分は「買い物リストに追加」で買い物リストへ入れる（発生源「防災の不足」）。

4.4 献立

案A 定番レシピDB（基本）

  • マッチング規則: レシピの材料タグと在庫を照合し、在庫にある材料が多いレシピを上に出す。同程度なら、設計案経過日数の多い材料やピン付きの材料を使うレシピを優先する（S1）。
  • 材料タグ: レシピごとに主要材料を品目マスタの品目で付ける。
  • 設計案初期レシピ: よく作る家の定番から30品で開始する（S3）。

案B AI相談文コピー（補助）

  • 設計案相談ボタンの場所: 献立候補の一覧の下に「AIに相談する文をコピー」ボタンを置く。
  • 設計案テンプレートの構成要素（例）:在庫の品目と数量、経過日数の多い品とピン付きの品、人数、避けたい食材、作りたい品数。
  • コピーの流れ: ボタンで相談文をクリップボードにコピーし、利用者が自分の使っているAIサービスに貼り付けて相談する。
  • アプリ側はAIを使わない（D4）。アプリは相談文を組み立ててコピーするだけで、AIへの送信や結果の取り込みはしない。

併用の日常フロー

  1. 献立候補を見る案Aの候補が、在庫・経過日数・ピンの順で並ぶ。
  2. 決まらなければ相談する相談ボタンで相談文をコピーし、外部のAIで相談する。
  3. 献立を決める案Aのレシピを選ぶか、相談で決めた献立を手入力する。
  4. 在庫と買い物リストに反映する不足食材は買い物リストへ入り、使った分は在庫から減る（連携③）。

4.5 買い物リスト

  • 発生源は3つ: 在庫減献立の不足防災の不足。項目ごとに発生源を記録する。
  • 消し込み: 買った項目にチェックを付けると、支出の下書きができる。金額は本人が入力・確認して確定する（D3）。
設計案実装ルート例（S2）: / ＝家計簿、/expenses?tab=list|stock|bosai

5連携ルール

D3 の5本。どれも金額は自動確定しない。金額が関わるものは下書きにして本人が確定する。

設計案各カードの「起きる画面（例）」は実装の目安で、決定事項ではない。

①消し込みから支出の下書き

買い物リストで項目を消し込むと、支出の下書きを作る。

起きる画面（例）:買い物リスト／支出ハブ（一覧）
区別: 下書き確認（本人が金額を確認して確定）

②在庫減から買い物リストへ

在庫の数量が減ってしきい値を下回ると、買い物リストに入る。設計案しきい値は設定値（品目ごと任意）。

起きる画面（例）:在庫
区別: 自動（金額は関わらない）

③献立決定から不足食材と在庫減

献立が決まると、不足食材が買い物リストに入り、使った分が在庫から減る。

起きる画面（例）:献立／在庫／買い物リスト
区別: 自動（金額は関わらない）

④優先付けで献立候補の先頭へ

期限ではなく経過日数とピンで優先を付け、該当の材料を使う献立候補を先頭に出す（D3。経過日数とピンの具体仕様は S1（設計案））。

起きる画面（例）:献立
区別: 自動（並び順のみ）

⑤購入価格の蓄積と食費の見通し

品目ごとの購入価格を家計簿に蓄積し、食費の見通しに使う。

起きる画面（例）:家計簿ホーム／グラフ
区別: 自動集計（元になる価格は確定済みの支出のみ）

6データ項目

エンティティ主な項目期限
支出日付、金額、カテゴリ、品目、数量、メモ、状態（下書き／確定）なし
在庫品目品目、数量、保管場所、登録日（自動）、ピン、補充の目安数量（任意・設計案）なし（D5）
防災備蓄品品目、数量、保管場所、区分（水・食料・赤ちゃん用品）、期限あり（唯一）
レシピ名前、材料タグ（品目）、人数なし
買い物リスト項目品目、数量、発生源（在庫減／献立の不足／防災の不足）、消し込み済みなし

品目マスタとカテゴリは家計簿と在庫で共有する。支出・在庫品目・防災備蓄品・レシピ・買い物リスト項目は、同じ品目マスタを参照する。

保管場所「防災庫」の区別: 保管場所が「防災庫」の在庫品目は、置き場所を示すだけで期限を持たない。期限を持つのは、防災登録チェックを付けて防災備蓄品として登録した品だけとする。両者は別のエンティティとして持ち、防災備蓄品であるかどうかはエンティティの種類で判定する（保管場所の値では判定しない）。

7アラートとバッジの規則

  • 対象: 防災備蓄品の期限のみ。
  • バッジ数字: 支出タブに、期限が数日以内の防災備蓄品の件数を出す。日数のしきい値は設定値として実装する。
  • ホームのカード: 表示するのは優先度が最も高い1枚だけ。
  • 通常在庫: アラートとバッジの対象外。在庫画面の経過日数表示とピンで確認する。

旧レポートとの差分

  • UI検討レポートにあった「期限が近い在庫」カードは廃止する。
  • 家計簿ホームのアラートカードと支出タブのバッジは、防災備蓄の期限だけを対象にする。
  • 献立の優先付けは賞味期限ではなく、経過日数とピンで行う（D5・S1）。
